## 1. Why JavaScript can be a pain point

Some developers think JavaScript can be hard to work with because of its asynchronous behavior, loose typing, and the web environment.

Asynchronous code can be confusing because things don’t run in order. For example, a function might not finish before the next line runs, which can make bugs harder to track.

Loose typing can also cause problems because variables don’t have fixed types. This can lead to unexpected behavior, like adding two numbers as strings instead of actual numbers.

The web platform itself is also complicated because different browsers may behave slightly differently, and developers have to deal with many APIs and events.

---

## 2. Why JavaScript is loosely typed and asynchronous

I think JavaScript was made loosely typed to make it easier and faster to write code, especially for beginners. Developers don’t have to worry about declaring types, which speeds up development.

Asynchronous features were likely added because JavaScript runs in the browser and needs to handle things like user input, network requests, and timers without freezing the page. This allows websites to stay responsive.

---

## 3. Compiled vs Interpreted languages

A compiled language is translated into machine code before running, like C++ or Java. An interpreted language runs line by line at runtime, like JavaScript.

JavaScript is mainly interpreted.

The benefit of interpreted languages is that they are easier to test and debug quickly. You don’t need to compile every time you make a change.

The drawback is that they can be slower and sometimes less strict, which can lead to more runtime errors.

## 4. Why focus on vanilla JavaScript

The professor is focusing on vanilla JavaScript so we understand the fundamentals before using frameworks.

Learning vanilla JS helps us understand how things actually work under the hood. It also makes it easier to learn any framework later, since most frameworks are built on top of JavaScript.

If we don’t learn a framework, we might be slower when building large applications, since frameworks provide tools and structure that make development faster.
